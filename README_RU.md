# ROS2: камера и управление TurtleBot3 жестами

Проект для задания от 17 ноября. Целевая среда: Ubuntu 24.04, ROS2 Jazzy, TurtleBot3 Burger в Gazebo. Камера настоящая, робот в симуляции.

## Установка

Запустить `python3 setup.py` внутри Ubuntu от обычного пользователя. Скрипт копирует проект в `~/ros_camera_robot`, устанавливает официальные пакеты ROS2 и Ubuntu, загружает репозиторий симуляции ROBOTIS (ветка jazzy) и модель MediaPipe. Потребуется пароль sudo. Скрипт не запрашивает и не сохраняет пароль самостоятельно.

После установки: `bash ~/ros_camera_robot/run_demo.sh`. На рабочем столе создаётся ярлык ROS2 Camera TurtleBot.

Камера: VirtualBox → Devices → Webcams → USB2.0 HD UVC WebCam. При следующем запуске виртуальной машины её может потребоваться подключить повторно.

## Жесты

| Жест | Действие |
|---|---|
| Указательный палец вверх | Вперёд, 0.10 м/с |
| Два пальца V | Назад, 0.10 м/с |
| Большой палец вверх | Поворот влево, 0.45 рад/с |
| Большой палец вниз | Поворот вправо, 0.45 рад/с |
| Открытая ладонь, кулак, рука исчезла | Стоп |
| Две руки, неуверенное распознавание | Стоп |

Нажать ENABLE в окне камеры. Показывать одну руку ладонью к камере. Для движения удерживать жест не менее 0.35 с, при уверенности модели от 0.70. STOP/DISABLE отключает движение до нового нажатия ENABLE. При прекращении распознавания свежих кадров команда становится нулевой через 0.65 с плюс один период публикации (0.1 с). Это программная мера для учебной симуляции, не сертифицированная аварийная остановка физического робота.

## Архитектура

`camera_publisher` читает веб-камеру OpenCV и публикует `sensor_msgs/msg/Image` в `/camera/image_raw` (BGR8, целевая частота 10 Гц).

`gesture_robot_controller` подписывается на изображение, распознаёт жест MediaPipe и публикует `/cmd_vel`. Тип `Twist` или `TwistStamped` выбирается при запуске по реальному топику симулятора. Обработка изображений выполняется в отдельном потоке, чтобы она не блокировала таймер остановки. В очереди хранится только последний кадр.

Используется ROS_DOMAIN_ID=37 и обнаружение только на localhost; проект предназначен для симуляции на этом компьютере. Для физического TurtleBot нужна отдельная настройка и проверка.

## Проверка и демонстрация

1. Запустить проект, дождаться Gazebo и окна камеры.
2. Показать модель TurtleBot3 и движущееся изображение с настоящей камеры.
3. Нажать ENABLE, последовательно показать 1 палец, V, большой палец вверх и вниз.
4. Показать ладонь и убрать руку: робот должен остановиться.
5. Нажать STOP: последующие жесты не должны двигать робота, пока снова не нажать ENABLE.
6. Снять подключение камеры: проверить нулевую скорость. Затем заново запустить демонстрацию.

Команды для терминала, в котором выполнен `source /opt/ros/jazzy/setup.bash` и `export ROS_DOMAIN_ID=37`:

```bash
ros2 node list
ros2 topic list -t
ros2 topic echo /gesture/status --once
ros2 topic echo /cmd_vel --once
ros2 topic hz /camera/image_raw --qos-reliability best_effort
```

Логи сохраняются в `~/ros_camera_robot/logs`. Они не содержат фото или видеозаписей. `commands.jsonl` фиксирует изменения команды, жест и уверенность модели. Нельзя выдавать результаты тестов логики за проверку распознавания живой руки: это отдельный этап демонстрации.

## Проверено на ноутбуке 18 ноября 2026

Проект установлен и запущен в Ubuntu 24.04.4 внутри VirtualBox. ROS2 Jazzy и Gazebo работают, три пакета симуляции собраны. Восемь тестов логики прошли и на Windows, и в Ubuntu.

Вживую проверены четыре команды жестов, движение вперёд и назад, правый поворот, остановка при исчезновении руки и кнопка STOP. Левый поворот проверен по выдаваемой угловой команде. В ROS видны оба узла проекта, поток Image и команды TwistStamped. Короткое измерение потока изображений показало примерно 10 Гц. Подробные наблюдения и ограничения находятся в `VALIDATION.md`.

Для повторного запуска установка заново не нужна:

```bash
bash ~/ros_camera_robot/run_demo.sh
```

После отключения и повторного подключения камеры перезапусти демонстрацию: автоматическое переоткрытие камеры не реализовано. Сначала закрой текущую демонстрацию через Ctrl+C в её терминале, затем выполни команду запуска. Если робот мелкий в Gazebo, нажми правой кнопкой на `burger` в Entity Tree и выбери Move To.

Gazebo на этом ноутбуке работал медленнее реального времени (коэффициент примерно 0.31–0.41). Держи кисть целиком в кадре; при неуверенном распознавании команда обнуляется. Сценарий защиты и ответы на вопросы находятся в `DEMO_RU.md`.
