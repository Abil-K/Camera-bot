# Демонстрация и объяснение проекта

## Перед занятием

Запустить Ubuntu в VirtualBox, подключить веб-камеру через Devices → Webcams и выполнить:

```bash
bash ~/ros_camera_robot/run_demo.sh
```

Дождаться Gazebo и окна камеры. Проверить, что изображение меняется. В начале движение отключено. Держать ладонь перед камерой целиком, при хорошем освещении; показывать только одну руку.

## Что показать за 2–3 минуты

1. Показать модель TurtleBot3 Burger в Gazebo и живое изображение камеры.
2. Нажать ENABLE. Поднять один указательный палец и удерживать жест: движение вперёд.
3. Показать два пальца буквой V: движение назад.
4. Показать большой палец вверх, затем вниз: поворот влево, затем вправо.
5. Открыть ладонь и убрать руку: нулевая команда скорости.
6. Нажать STOP/DISABLE. Повторить жест движения: робот остаётся остановленным до нового нажатия ENABLE.

## Объяснение на английском

“This project uses two ROS 2 nodes. The camera node captures webcam frames with OpenCV and publishes standard Image messages. The robot node subscribes to the image topic and uses MediaPipe to recognise hand gestures. It converts a recognised gesture into linear or angular velocity for TurtleBot3 in Gazebo. Motion starts only after manual enabling and a stable gesture. Invalid or stale input produces a zero velocity command.”

## Ответы на вопросы

**Что такое node?** Отдельный участник ROS 2. Здесь один отвечает за камеру, второй — за обработку изображения и команду движения.

**Что такое topic?** Именованный канал сообщений. `/camera/image_raw` содержит `sensor_msgs/msg/Image`; `/cmd_vel` содержит скорость в формате, который использует установленный симулятор: `Twist` или `TwistStamped`.

**Где здесь computer vision?** Изображение BGR преобразуется в RGB, модель MediaPipe определяет руку, её ориентиры и класс жеста с оценкой уверенности. OpenCV захватывает кадры и рисует результат.

**Как исключаются краткие ложные команды?** Нужны одна рука, уверенность не менее 0.70 и одинаковый жест не менее 0.35 секунды. При смене направления сначала выдаётся нулевая скорость.

**Что происходит без свежих кадров?** Контроллер проверяет возраст результата. Через 0.65 секунды без подходящего свежего результата он выдаёт ноль на следующем цикле публикации, который запланирован каждые 0.10 секунды. Это программный механизм для учебной симуляции; он не гарантирует физическую безопасность при зависании всего компьютера.

**Почему очередь из одного кадра?** Для управления важнее последнее изображение. Длинная очередь увеличила бы задержку между жестом и реакцией.

**Это реальный робот?** В этой конфигурации используется реальная веб-камера и виртуальный TurtleBot3 в Gazebo. Для физического робота нужны отдельная настройка связи, ограничения движения и независимый механизм остановки.

**Что действительно проверено?** Смотреть `VALIDATION.md`. Не называть тест или демонстрацию успешными, если соответствующая проверка ещё не выполнена.
